# 功能与研究效果验证标准

版本0.3；本项目制定的执行规则。参考材料及适用边界见[公开依据](references.md)。

## 每项功能的定义与完成条件

开发前必须登记：使用者要解决的研究决定、输入/来源/期间/会计范围、输出、传导、替代解释、最危险的失败、验证数据、预期行为、通过门槛及不支持用途。无数据时说明补证或弃权策略，不能用默认数字补齐事实。模板与JSON注册表共同维护。

完成状态分别为计划、实现、功能验收、研究方法评审、前瞻校准。功能验收要求相关反例、公式和流程检查通过，并附实际结果；研究方法评审另外需要合适的经营机制、参数依据、反方处理与能力边界。概率或预测有效性的声明需要真实前瞻数据。任何一层都不能因上一层通过自动晋级。

## 八类检查

| 层次 | 检查方法 | 会判失败的情况 | 结果可以说明什么 |
| --- | --- | --- | --- |
| L1 算术与软件 | 已知解析答案、独立等价方法、输入边界、事务与回归 | 负股息、错误期间、并发覆盖、缓存新旧混搭 | 软件是否按声明执行 |
| L2 原文与口径 | 原页/上下文、期间、单位、币种、范围、版本；争议回看页图 | 哈希正确但提取数字错、母行混集团、假设当实际 | 该条陈述是否受原文支持 |
| L3 证据充分性 | 主张→证据→区分性观察；检验相反解释 | 引用存在但无关、转载重复、来源已过时 | 判断的证据基础及未知 |
| L4 财务与估值 | 业务驱动、利润现金桥、资本/融资、实际到预测；独立合理性检查 | 事件改变实际但预测无桥、终值独占且无依据、银行分配不受资本约束 | 方法是否适用于该公司和用途 |
| L5 结论与反方 | 同样事实、最强反方、推翻条件、补证与修订日志 | 自动肯定、反方只装饰、强行给价或概率 | 过程是否允许纠错与弃权 |
| L6 开发/保留样本 | 预写答案、对照简单基准、遮蔽主体、样本分组、专家裁定 | 用已公开答案调试后称盲测、只挑成功大公司 | 在该组问题上的实际表现 |
| L7 前瞻结果 | 事前固定对象/期限/结算、保留弃权失败、同基准率比较 | 事后改阈值、重复事件当独立样本、删失败 | 该类预测的校准与适用边界 |
| L8 运行交付 | 进程、DB/worker健康、代表页面、重启、失败任务、恢复 | 截图成功但结束即停、HTTP200但内容错、恢复缺原件 | 当前访问及恢复路径可用 |

L2–L7的语义充分性不能全部由当前规则证明。AI或开发者的自检不等于独立金融专家复核。

## 六家公司案例库怎么用

已有六家是开发回归集。候选题覆盖真实口径陷阱，并附原文定位；预期答案要由具备相应行业/会计知识的人重新裁定。每题保存问题、当时资料集合、可接受答案及限定、应当弃权项、严重错误类型、评审者与分歧处理。

原始财务答案优先来自公开原文，不以fixtures或当前模型输出作为答案权威。未知经营原因不编标准答案。以后新增未用于开发的公司、不同市场、失败/退市案例及新期间作为保留集；禁止在看结果后更改通过门槛。

先比较“只读财报摘要”“上一轮判断不变”“简单指标规则”等明确基准，再评价完整流程是否减少决定性错误、发现更多关键反证并节省人工核查。基准和样本量在研究方案里预先确定，本次不预设无依据的命中率或统计显著性。

## 发布门槛与证据

`scripts/quality_gate.py`逐项保存测试ID与结果、源码摘要、功能合同、原件核验以及可选本地健康检查。它只授予受限本地功能使用状态，始终单独报告 `research_decision_ready=false`，直到后续有足够研究评审证据。

每次交付保存命令、日期、版本/工作区摘要、实际通过/失败/未运行、允许用途和剩余问题。例外应列明，不能写成“全部完成”。界面交付至少一次真实操作并在工具会话结束后再次探测存活；后台运行不等于电脑重启后自动启动，也不等于远程生产。
