# 三层平台与研究体系方案

版本0.4，2026年10月25日。由用户本轮明确的三块结构驱动，优先于此前仅以六家公司组织网站的表达。需求依据见[用户需求](requirements.md)，完整领域设计见[方案设计](solution-design.md)。

## 核心结论

Personal Financial Analyses 是个人中长期研究的工作平台。平台基础解释研究怎样成立，市场层提供时点环境，行业层把变量连接到商业机制，公司报告展示这套方法的实际应用。公司是研究对象，不能承担整个平台的信息架构。

参考Bloomberg公开产品把数据、经济、图表、分析和工作流结合的建设方式，但不声称拥有它的数据、研报、授权、交易或实时覆盖能力。[Bloomberg产品](https://professional.bloomberg.com/products/)

本版最重要的架构补齐是：**理论/知识 → 工作流与审查 → 来源/市场观察 → 行业机制 → 公司证据与模型 → 条件报告 → 下一验证**。每条连接均区分当前事实、待证解释、未来预测及能力规划。界面连接不代表经济因果已经被验证。

## 第一层：平台及整体研究基础

| 模块 | 用户需要知道什么 | 本地实现及边界 |
| --- | --- | --- |
| 平台总览 | 服务谁、输出什么、目前可信到哪一步 | 个人深度研究，全球方法、三市场适配；公开数据与本地工作台 |
| 理论与工作流 | 为什么如此研究、如何补证和停止 | 能力圈、所有者收益、资本回报、机会成本、竞争解释与十步工作流；原文链接和适用边界 |
| Agent策略 | 谁读什么、输出什么、何时返回补证 | 七种职责合同、输入/输出/约束/当前状态；没有运行中的自主AI研究团队 |
| 知识与文档 | 方法是否可累积、知识如何组织 | 理论经验、会计口径、行业手册、时点证据、判断复盘；可在网站打开Repo正式文档 |
| 审查与验证 | 发现过什么错、哪些已修、哪些尚未证明 | 公开自查结论、控制反例、逐功能合同、功能报告与当前源码匹配状态 |
| 建设与扩展 | 下一步做什么、如何验收 | 行业驱动桥→来源及定价→未见/前瞻评价；付费数据和远程部署尚未确定 |

研究立项先明确用途和期限；不是先抓取很多资料再寻找一个观点。平台知识只为提出更好问题和检查机制，不把大师观点当作对六家公司的评级，不通过多个模型“赞成票”生成可信度。

## 第二层：重点数据、信息源和大盘

覆盖结构为权益大盘、利率流动性、信用、波动、FX、商品、经济政策、市场宽度资金。每项至少保留定义、地区、单位、观察日、取得日、来源、滞后、缺失、最近获取及传导对象。

首批选定公开指数/汇率/期货JSON可以尝试获取；FRED利率/信用/现货保留本次页面转录并尝试直连；中国利率、社融、PMI、地产、美国就业通胀、香港流动性和市场宽度等显示待接入。展示目录是为了暴露覆盖缺口，不能称完成全市场实时接入。

一项市场变动进入研究需回答六个问题：

1. 观察本身可靠吗？是否同定义、同定盘、同交易日，是否修订/换月/缺失？
2. 变化源于何种冲击？有政策/事件原文吗？没有时只记录观察，不补造原因。
3. 公司资产、负债、客户、供应链和计价币有何净暴露？谁承担、谁能转嫁？
4. 经什么时滞、合同、套保、竞争或政策抵消，影响量价成本、现金和资本？
5. 是否改变已有盈利/估值假设？有同口径输入才重算，否则进入补证。
6. 与市场此前预期相比是什么？没有价格/共识/时点资料时，不能称利好已反映、超预期或低估。

看板阈值是研究关注条件，未经校准。市场大涨大跌本身不生成买卖操作。既有公司监测（宁德单季现金、腾讯现金口径）继续保留；宏观自动归因和自动更新盈利参数尚未实现。详见[市场框架](market-framework.md)。

## 第三层：行业与公司研究

采用自定义经济机制分类，四个上层组、六种行业手册。借鉴GICS层级思想，但不是正式GICS授权分类或指数成分映射。[MSCI GICS](https://www.msci.com/indexes/index-resources/gics)

| 上层组 | 行业手册与案例 | 决定性差异 |
| --- | --- | --- |
| 科技与平台 | 软件云/MSFT；数字平台/腾讯 | 用量/商业化、AI经济投入、递延与投资资产，不能只看收入增长 |
| 消费 | 会员零售/Costco | 会员层级、续费观察滞后、费率现金与递延收入、门店经济性 |
| 制造与能源转型 | 汽车/BYD；电池/CATL | 量价成本/组合、材料传导、渠道/票据/账期、扩产与融资 |
| 金融 | 商业银行/CMB | NII、信用迁徙、普通股、RWA/CET1、存款与可分配资本 |

每个行业手册必须有结构与问题、KPI、利润现金资本桥、估值方法、宏观通道、最强反方、下一验证、原始方法依据。新增公司必须先选择或改建行业手册，不能简单复制另一家公司参数。详见[行业与报告合同](industry-research.md)。

公司默认打开研究报告，而不是资料操作页。报告由当前研究台账组合，保留原文、核验、缺口、模型与结论状态；原有六步操作仍可进入。报告是草案，不是新发布的投资意见。

## 数据与技术关系

| 对象 | 存放 | 性质与更新 |
| --- | --- | --- |
| 平台方法、行业手册、市场目录 | `knowledge/*.json` | Git管理、重启加载；方法/覆盖定义可审阅 |
| 正式设计和审查 | `docs/` | Git管理；网站通过白名单只读文档接口展示 |
| 公司原文/事实/模型/结论 | SQLite记录+本地原件 | 保留版本与来源依赖，不覆盖旧结论 |
| 市场原始响应/页面转录 | 忽略的`data/market/raw` | 保存SHA、取得方式和时间；转录不是自动直连 |
| 市场快照/尝试 | SQLite独立kind | 成功追加快照，失败追加尝试；失败不改变旧观察日 |
| 市场刷新任务 | SQLite jobs，`_market`命名空间 | 与公司原文队列分开消费，去重、显式触发；非定时监控 |
| 动态报告 | 只读组合API+JSON导出 | 公司修订+行业/市场背景摘要；不自动改写模型或发布结论 |
| 功能验收 | `quality/features.json`和检查报告 | 方法/研究/预测状态分别记录；检查摘要含知识目录 |

本地仍使用Python/SQLite/原生Web模块化单体。没有为三块结构另起云应用或付费服务。新增接口：`/api/platform`、`/api/industries`、`/api/markets`、`/api/reports/{issuer}`、`/api/library/{白名单ID}`，以及有本地令牌校验的市场刷新POST。

市场响应不写入公司已核验事实，也不自动变更个股评级。报告中的新市场背景与旧结论并列时，明确显示背景未触发自动重算。未来若允许市场变量驱动模型，必须把暴露、时滞、假设桥与快照ID进入模型依赖和旧结论失效规则。

## 当前审查结论与扩展顺序

0.3纠正了访问、证据类型、口径/期间、冲突回退、无效通过等问题。现阶段允许作为证据、算术、示例敏感性和人工研究工作台；行业预测桥、语义反方、参数承保、现价判断和前瞻效果仍未通过验收。0.4补齐结构与研究内容，不能据此提升上述质量判定。

下一阶段优先：BYD量价/现金投入融资桥，CATL出货材料/营运资本桥，CMB息差信用/资本分配桥；再完善微软AI经济回报、Costco会员与门店、腾讯投入与投资资产。每家公司先完成一条能改变预测的实质机制并留独立计算反例，然后扩大模板。

来源稳定性、证券身份、价格/共识时点和参数依据完善后，再做当前证券经济性。专家未见样本和前瞻登记/结算用来评价效果，历史事后解释不能替代。黑天鹅不能由仪表盘保证预测；通过融资、杠杆、集中、期限错配和联合压力降低脆弱性。[SVB审查](https://www.federalreserve.gov/publications/review-of-the-federal-reserves-supervision-and-regulation-of-silicon-valley-bank.htm)

## 本轮验收合同

F13验证三层导航、方法与Agent状态不夸大；F14验证bp、百分比、缺失、同日曲线、未来值、来源失败与完整性；F15验证来源和文档可追查；F16验证六行业覆盖、报告结构、示例及旧结论状态不被重写。功能完成与研究效果是不同验收。浏览器检查三个主入口、方法/文档、市场筛选及传导、行业筛选、报告与原文、窄屏，记录在[0.4验收](validation/local-v0.4.md)。
