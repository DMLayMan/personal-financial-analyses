# Personal Financial Analyses 开工条件与待定输入

版本 0.2
评估日期 2026年10月25日

用户已授权按默认方向启动本地首版，0.2已有可操作的完整研究链与六家公司验收。运行方式见[本地指南](local-development.md)。持续跨市场运行、付费数据和远程访问仍有分阶段依赖，不能将本地实现描述为生产条件全部就绪。

## 对用户目标的理解

- 建立长期积累的个人商业与金融研究能力，以公司与行业理解为基础。
- 以中长期深度研究为主，兼顾日常事件和高危风险。
- 方法面向全球，分别处理美股、港股、A股的数据与证券差异。
- 研究要有原始证据、竞争解释、主动补证、模型、反方和条件结论。
- 借鉴专业机构及投资思想，允许否定原判断，重视历史、失败和不可知信息。
- 结论方向与可信度可解释，预测概率需定义和校准，不能用虚构分数包装可靠性。
- 应用提供统一工作流程，界面服务于研究内核；当前先完成设计持久化。
- 项目名称为Personal Financial Analyses，全部正式文档与未来的源代码由Git管理。

## 可以按默认推进的事项

以下为方案默认，不冒称用户已经逐项批准。后续如有新输入应更新设计和范围。

| 决定 | 建议默认 |
| --- | --- |
| 首期访问 | 个人私有、本地运行的开发环境；之后按实际需要部署 |
| 应用形态 | 适配手机的Web应用，兼顾桌面深度研究 |
| 语言与时区 | 简体中文，用户时间Asia/Shanghai，保留原市场时区 |
| 第一批资料 | 真实公开披露，支持受控人工导入与核验 |
| 起步样本 | 先沿用已验证六家作为验收素材，长期覆盖名单可调整 |
| 外部消息 | 先提供应用内队列和日历；外部推送在渠道确定后接入 |
| 费用 | 不因设计文档而采购或订阅新服务；发生费用前明确预算与权限 |
| Git远端 | 先完成本地管理，远端归属与可见性明确后再同步 |

## 需要用户输入的事项

| 输入 | 何时需要 | 不提供时如何推进 | 是否阻塞本地基础开发 |
| --- | --- | --- | --- |
| 数据和模型服务的月度预算，是否接受付费来源 | 采购、收费API或持续模型调用前 | 先用公开资料及受控导入，付费能力标缺失 | 否 |
| 访问与部署偏好，是否需要手机异地访问、是否仅个人使用 | 生产部署及外部访问前 | 本地单用户开发，部署保持未决 | 否 |
| 已有数据服务、API、券商或研究资料权限 | 对应来源接入前 | 不假定继承会话连接，保留候选与备用路径 | 否 |
| 第一批长期关注公司与行业，研究频率和优先问题 | 定制覆盖与提醒前 | 用现有六家验收，避免把它们当推荐组合 | 否 |
| Git远端平台、仓库归属及可见性 | 远端创建或推送前 | 仅本地提交，不自动创建公开仓库 | 否 |
| 持仓、资金期限、流动性与风险约束 | 做个人组合或仓位建议前 | 保持公司、行业和证券公共研究层 | 否 |

凭据在来源接入时通过适当配置方式提供，不写入文档或Git。当前不要求用户先上传持仓，也不需要用户为所有行业定义一套完整规则。

## 按阶段判断开工条件

| 工作 | 准备程度 | 关键剩余条件 |
| --- | --- | --- |
| 文档持久化和Git基线 | 本次完成范围 | 检查链接、需求映射及提交状态 |
| 本地完整研究流程开发 | 0.2已实现并按六家验收 | 继续深化驱动、自动取证和独立估值复核 |
| 三市场持续自动更新 | 部分条件具备 | 逐来源权限、频率、稳定性与失败恢复验收 |

| 付费共识和替代数据 | 未准备完成 | 预算、供应商字段与授权确认 |
| 可验证预测概率 | 尚未验证 | 真实前瞻登记、到期结果、足够同类样本与基准比较 |
| 个性化组合动作 | 输入不足 | 账户目标、持仓、期限、损失与交易约束 |

## 后续实施前应遵守的边界

首版已实现资料获取、来源与版本、研究问题、补证、可复算情景、反方、条件结论和日志。不能因为界面可用就宣布完整研究、持续自动监控或预测能力已经通过验证。

如用户不另行改变方向，已有目标无需再次确认。真正影响费用、对外访问、数据权限或个性化动作的输入，在相应阶段收集；技术选型和一般实现细节由实施者负责。
