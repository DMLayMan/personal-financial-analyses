# Personal Financial Analyses 用户需求

版本 0.4
日期 2026年10月25日
依据 本项目当前对话中用户的需求与选择

这份文档整理用户希望建立的个人商业与金融分析平台。用户先要求完成体系设计和持久化，随后明确授权启动本地首版。研究规程、数据架构和工程方案在其他文档中维护，避免将实现建议混入用户原始要求。

“大体思路没有问题”作为对当前方向的认可，不解释为对所有技术选型、数字阈值、供应商、费用和上线范围的逐项批准。

## 用户目标

用户希望获得一套长期可用的个人商业分析能力：理解公司如何赚钱、盈利质量、未来潜力及行业变化，参考专业机构和长期投资实践，以持续证据形成判断，并能够解释何时需要更新、补证、等待或放弃。

目标用户首先是个人深度研究者，以中长期投资为主，兼顾事件风险。方法面向全球，数据和市场规则分别适配美股、港股和 A 股。

## 分析与决策需求

公司研究应回答利润来源、竞争机制、增长约束、资本投入、盈利质量、治理与融资韧性。行业模板需要反映经济机制差异，不能将一般制造业的现金流或估值指标直接套用于银行等行业。

研究过程应能够被复核：明确问题和时间范围，记录支持与反对证据，解释业务到财务的传导，保留关键假设与未知，形成有条件的结论。新证据能够推翻既有判断，修改时保留旧版本和原因。

结论方向应说明判断对象和比较基准。经营改善、证券估值吸引力及个人账户适宜性分别表达。可信度应有可解释标准；未经过校准的主观判断不能包装成已经验证的上涨概率。

大师思想用于提问、约束和反证。不得假称某位投资者对当前标的作出判断，也不得以多个视角赞成替代证据核查。

## 数据与监测需求

关键事实和计算应保留来源、期间、单位、币种、合并范围、版本和首次公开时间。公司原文、管理层说法、研究者推断和情景假设需要可区分。

日常监测围绕研究判断与关键变量进行。提醒需要解释发生了什么、影响路径、重要性、证据缺口、下一步动作和验证时点。旧消息、转载、微小修订和重大风险应采用不同处理方式。

关键数据缺失、过期、冲突或获取失败应直接显示，不得将缺失值当零，也不得因没有提醒就表示没有风险。

## 产品范围

| 层次 | 当前范围 |
| --- | --- |
| 已确定的用户范围 | 个人使用者；公司与行业深度研究；中长期投资为主 |
| 已确定的市场范围 | 全球方法；首期分别考虑美股、港股、A 股 |
| 已认可的方法方向 | 研究问题、证据、竞争解释、补证、模型、反方、条件结论、监测与校准 |
| 当前任务 | 本地首版研究流程实现与六家公司验收 |
| 实现形式建议 | 先建立适配手机的 Web 应用，以同一套数据支持深度研究与变化查看 |
| 后续按需要扩展 | 完整共识、更多行业、组合分析、其他数据与更复杂工具 |

原生手机客户端、公开多用户服务、实时逐笔行情、具体数据供应商和预算尚未逐项确定。它们不能被视为当前已经批准的范围。

平台辅助个人研究和决定。针对账户的仓位建议需要相应的期限、持仓、流动性和风险约束输入。当前任务不包含账户连接或自动交易实现。

## 关键原始表达

- “核心无非是几个点”包括日常事件及对公司、行业的影响，以及数据波动后的判断与操作。
- “重点不是应用的表达……这个东西的内核是更重要的。”
- “切记不要自嗨。”
- “绝对不只是一个大家游玩的demo。”
- “如果信息不够，是否要拿更多数据？中间的决策过程是怎么做的？”
- “最终结论的输出是正向的、负向的，结论的可信度是多少？”
- “把我当前的一些需求描述和要求，单独整理成一份需求文档。”
- “整个项目还是用Git管理……Personal Financial Analyses。”
