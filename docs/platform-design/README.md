## 当前范围

- 用户：个人深度公司/行业研究者，以中长期投资为主，兼顾事件风险。
- 市场：全球方法，美股、港股、A股分别适配身份、口径、时区、披露和证券定价。
- 平台：左侧三个入口，分别为平台与研究基础、市场与信息看板、行业与公司研究。
- 实现：本地Python/SQLite工作台；已发布的本人私有云工作台；六家公司动态证据草案；两份有日期的BYD/AI专题。
- 用途：资料与证据核查、历史算术、条件研究、示例敏感性和研究版本。完整公司预测、现价投资评级、独立审议与前瞻效果尚未通过验收。
- 更新：公开来源按需获取；无页面关闭后的常驻研究、连续实时监控或外部模型自动研究服务。

## 文档职责与历史

1. 当前产品与工程方案以本目录为统一入口，新增设想标为规划，不能自动成为已确认范围或已实现能力。
2. [原始需求基线](../requirements.md)保留UR/AC编号和用户确认状态；[早期技术基线](../solution-design.md)保留演进记录。旧文件不删除、不静默改写过去结论；发生冲突时先核对日期、实际代码和新验收。
3. [研究规程](../research-methodology.md)、[市场框架](../market-framework.md)、[行业合同](../industry-research.md)维护领域规则，PRD规定它们怎样成为产品输入和输出。
4. [功能合同](../../quality/features.json)、[质量审查](../quality/review-2026-10-25.md)、[专题审查](../quality/focus-research-2026-10-25.md)和[验收目录](../validation/)记录实际通过与未通过；写完方案不改变这些状态。
5. 应用运行与部署按[本地手册](../operations/local-service.md)、[私有云手册](../operations/hosted-service.md)执行；本目录不保存口令、个人数据库、持仓或下载原件。

## 维护规则

每次实质变更同步更新：用户需求/设计条目→功能合同F编号→源码与数据合同→验收结果→能力状态。产品文档版本、应用版本和研究报告版本各自管理。新财报更新研究版本，不应无理由改写平台需求；产品方案修订也不能让历史研究自动变为有效。

项目主仓库：[DMLayMan/personal-financial-analyses](https://github.com/DMLayMan/personal-financial-analyses)，公开，默认分支`main`。GitHub源码同步与Sites站点发布是两条操作链；本次文档整理不等于线上应用或研究数据已经更新。

2026-10-29更新：按用户要求，GitHub源码仓库改为public；该设置不改变Sites本人私有访问及研究数据的保存边界。
