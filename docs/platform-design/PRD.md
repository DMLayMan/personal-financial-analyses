# Personal Financial Analyses 产品需求文档

文档版本1.0｜整理日期2026-10-27｜应用基线0.6｜状态：当前产品方案与后续需求，逐项区分实现程度。

本PRD依据[用户需求基线](../requirements.md)、后续对话、现有源码及[质量审查](../quality/review-2026-10-25.md)整理。实现细节见[技术设计](TECHNICAL-DESIGN.md)，需求编号及实际证据见[追踪表](TRACEABILITY.md)。本次没有重新更新金融事实或作出投资评级。

## 1. 产品目标与核心问题

平台服务个人深度商业和金融研究：理解公司如何赚钱、利润能否持续、增长消耗多少资本、风险怎样传导，以及当前证券价格要求怎样的未来。方法全球通用，先适配美股、港股、A股；以中长期研究为主，兼顾重大事件风险。

用户需要看清的不仅是结论，还包括信息、判断和结论之间的过程：看了哪些数据，来源是否可靠，如何解释，什么尚不知道，是否值得继续补证，什么事实会推翻原判断。平台应长期积累可修订的方法、行业经验、原文和研究版本。

产品的核心产出是**有证据、可复算、可被反证和持续更新的研究报告**。平台方法与市场看板是报告的输入。公司列表、图表或Agent角色说明不能单独作为研究能力完成的证明。

### 1.1 需要改善的决定

| 用户问题 | 产品必须提供什么 | 不合格的替代品 |
| --- | --- | --- |
| 这家公司靠什么赚钱，优势可持续吗 | 业务分部、客户与竞争、单位经济性、资本回报和反证 | 公司百科与新闻堆积 |
| 盈利增长为什么不等于现金增加 | 利润调整、营运资本、投入、租赁、融资与普通股分配的桥 | 单一净利增速或通用总分 |
| 新事件真正改变什么 | 暴露、合同/时滞、量价成本、资金、估值假设及下一验证 | 标题直接标成利好/利空 |
| 当前价格是否合理 | 正常化盈利、完整资本索偿、未来假设及价格隐含条件 | 通用PE乘利润即称目标价 |
| 证据不足时怎么办 | 有针对性的补证、等待、限缩用途或停止理由 | 无限抓资料，或填默认值完成流程 |
| 研究判断是否值得信赖 | 事实/机制/预测/定价分别说明信心、审查及失效条件 | 模型自述胜率、引用数量或测试分数 |

### 1.2 已确定的约束

个人使用；优先公开数据；Git管理需求、方案、源码、选定公开字段及验证记录；本地与本人私有云可访问。界面三个主方向放在左侧，桌面支持深度核查，手机优先阅读和查看重要变化。付费数据、外部模型预算、账户连接、多人共享及自动交易尚不属于默认范围。

## 2. 用户与典型任务

| 角色/场景 | 进入平台时要完成的工作 | 期望产物 |
| --- | --- | --- |
| 个人研究者：首次覆盖 | 建立问题、能力边界、行业框架、证据与估值条件 | 首次覆盖草案及关键缺口 |
| 个人研究者：财报更新 | 核对最新披露、与旧假设比较、解释利润/现金差异 | 本轮变化、维持/修订判断和新版本 |
| 日常观察者 | 看市场、公告与来源健康，筛出值得深读的变化 | 待核查事件、影响通道和下一证据 |
| 研究复核者 | 检验引用相关性、口径、竞争解释及价格假设 | 实质反方、纠错或限缩结论 |
| 平台维护者 | 更新知识/行业模型/来源合同，执行验收与恢复 | 可追踪的版本、功能合同与真实检查结果 |

这些是同一个人在不同场景下的职责，当前不表示已经实现多用户权限系统或独立机构团队。

“已实现”表示有对应代码或人工产物；“部分实现”表示仍有重要覆盖/判断缺口；“规划”没有完成运行验收。三者都不能自动等同投资判断有效。

| 能力 | 当前状态 | 已有范围和明确限制 |
| --- | --- | --- |
| 左侧三层平台及行业入口 | 已实现 | 知识方法、市场信息、行业公司分开；不是全行业自动覆盖 |
| 公司证据与研究操作 | 部分实现 | 六家公司资料、候选、核验、缺口、示例模型、反方和结论记录 |
| 可维护知识 | 部分实现 | 草案/采用/停用及历史；采用不表示金融方法已验证 |
| 市场与公告 | 部分实现 | 选定公开序列/Fed及SEC元数据按需读取；来源会失败，未读正文不可当事实 |
| 动态证据报告 | 部分实现 | 可比实际、现金观察、依赖/快照、HTML导出；行业滚动预测未完备 |
| BYD与AI专题 | 已有人工研究版本 | 2026-10-25截点；AI八层与40标的行情索引不等于40家公司完整承保；不自动更新 |
| 本地运行与本人私有云 | 已实现且有范围验收 | 浏览器同内核、云版本保存；正常登录后全流程和真实手机仍须按记录解读，不许泛称全平台无缺陷 |

| 自动研究Agent、持续监控 | 规划 | 角色合同与人工流程存在；没有部署外部模型自动研究和常驻监控 |
| 独立专家/未见样本/预测校准 | 规划或未验证 | 已用开发样本不能称盲测；不显示已校准胜率 |

## 4. 信息架构与页面职责

三个主入口固定左侧；窄屏保留左侧紧凑入口，公司快捷入口只在第三层。导航名称保持稳定，每层可扩展子模块，避免每增一家公司就改整个平台结构。

### 4.1 第一层：平台与研究基础

平台总览说明服务对象、产物、真实能力和限制。理论与工作流说明经营、资本、价格、反方和停止条件。知识与文档管理方法、行业手册、会计定义、历史案例及出处。Agent策略展示职责和真实执行状态。审查与验证展示发现过的错误、如何修复、哪些还没证明。建设与扩展连接需求、优先级、验收与运行成本。

每项知识至少有稳定标识、正文、类别、来源、适用范围、条件/失效、变更理由、状态和版本。草案不覆盖采用版；采用/停用影响对应报告依赖。文字知识不能直接变成可执行公式，计算规则变更须另过金融与代码验收。

### 4.2 第二层：市场与信息看板

看板先回答当前市场环境、重要变动、证据覆盖和研究影响。指标至少显示定义、币种/单位、观察日、取得日、提供方式、延迟/缺失/失败状态和适用行业。单一“已接入”标签不足以描述来源能力。

| 指标组 | 重点观察 | 传导问题 |
| --- | --- | --- |
| 权益大盘与行业 | 指数、行业相对表现、市场宽度 | 盈利变化还是估值/风险偏好？缺材料时不编原因 |
| 利率与流动性 | 政策利率、期限曲线、香港及中国适用利率 | 融资成本、折现、存贷和期限错配 |
| 信用与波动 | 信用利差、波动指标、融资事件 | 融资窗口、抵押价值与客户违约风险 |
| 汇率与商品 | FX、能源、关键材料 | 净暴露、套保、合同、转嫁和时滞 |
| 经济、政策与供需 | 通胀/就业/PMI/信用、监管与行业数据 | 需求、税基、生效日期、地区和业务适用范围 |
| 来源健康 | 未读公告、失败、时效、修订/换月 | 没收到资料与没有变化必须分开 |

上述是覆盖结构，不代表每项已经自动接通。最新可得性以逐源尝试和原件为准，历史9成功/4超时等记录不升级为今天的服务保证。日常阅读模式为“关注→查原文→检查暴露→建立事件→补证/重算/暂缓”。

### 4.3 第三层：行业与公司研究

先展示行业经济机制、KPI、资本/现金、估值方法和风险，再展示公司怎样应用。当前六家案例分别为微软、Costco、腾讯、比亚迪、宁德时代和招商银行。行业分类为研究自定义经济机制，不冒充正式指数分类。

公司默认进入报告；资料提取和核验操作作为可下钻的证据工作区。专题区展示有明确截点和版本的BYD/AI完整报告。动态草案与人工专题必须同时标明产出方式、覆盖范围、来源和更新方式，不互相冒充。

## 5. 研究全流程与通过条件

| 步骤 | 必要输入与工作 | 输出/前进条件 |
| --- | --- | --- |
| Q0 立项 | 对象、证券、行业、期限、问题及可改变的决定 | 明确研究用途和未知；避免无目的全量抓取 |
| Q1 方法 | 适用理论、行业手册、历史参考类 | 明确适用与失效条件；不以大师观点直接评级 |
| Q2 取证 | 字段计划、主来源、备源、原文、时间/口径 | 原始/候选/核验分开，重要冲突保留 |
| Q3 解释 | 支持与反对证据、共同上游、竞争机制 | 写出至少一个能够实质改变判断的反方 |
| Q4 主动补证 | 影响判断的关键变量、可区分观察、来源及成本 | 补证相关性待审；不可得则限缩、等待或退出 |
| Q5 财务 | 实际→调整→业务驱动→利润→现金→资本/融资 | 有公式、来源和时点；缺融资不得假装现金可分配 |
| Q6 定价 | 证券身份、价格/股本/FX、资本索偿与未来条件 | 缺预测/正常化等保留条件测算，不给伪目标价 |
| Q7 审查 | 来源冲突、算术、因果、强反方、联合压力 | 裁定接纳/驳回/未解决及理由；同模型不是独立审议 |
| Q8 报告 | 分层结论、信心理由、缺口、下一证据与用途 | 保存冻结版本；未达门槛可产出未评级研究稿 |
| Q9 更新/复盘 | 新公告、模型偏差、失效与到期事件 | 说明变化理由，保留旧稿和失败；预测事先登记后结算 |

当前并非全部步骤均自动执行。状态和产物可以由人工完成；真正的语义审议、个股预测和持续监控仍按实际能力标注。

### 5.1 补证与停止

每个缺口写明：它限制哪个判断、合理范围内能否翻转判断、需要什么区分证据、下一来源、当前属于哪类未知、继续成本及停止条件。五类未知分别是资料未取得、原文已有未提取、口径未勾稽、经营机制未知、未来尚不能验证。

引用不相关、重复转载或来源同源不增加独立证据。足够证据只能由问题相关性和机制审议确定，不设“引用满N个自动通过”。可信范围内结论仍稳健时可结束本轮；关键变量不可知时允许暂缓，不强行补数。

## 6. 公司财务与证券分析合同

| 研究层 | 应做的工作 | 关键防错 |
| --- | --- | --- |
| 业务与竞争 | 客户需求、分部、收入单位、成本、优势和替代 | 集团增长不等于单一AI业务；批发不等于零售 |
| 盈利质量 | 原始/管理层调整/研究者正常化及税与归属 | 投资收益与经营利润、研发费用/资本化、补助、减值分别审议 |
| 现金与再投资 | CFO、营运资本、维持/增长投入、租赁、预付与承诺 | 总CapEx差额非自动FCFE；应付融资不可默认永久增长 |
| 融资与普通股 | 到期债务、可转债、永续、少数股东、期权/稀释 | 总债务含流动部分不能再加；不同现值口径不可硬相加 |
| 估值与预期 | 可持续盈利/现金、资本成本、情景、反向定价与价格 | 当前倍数非完整预测；私募投后值、ARR和GAAP不混用 |
| 行业差异 | 会员/递延、量价材料、平台算力、银行信用/资本等驱动 | 银行分红受资本约束；不能统一套增长率和PE |

情景必须标实际、指引、共识、自有预测或分析者假设。敏感性展示的是条件，不是统计区间；未有可结算事件和校准证据不显示胜率。A/H、ADR、不同柜台、财年及币种分别处理。

## 7. 核心报告输出合同

报告至少包括以下部分；数据不足时保留章节与具体缺口，不能用空话填齐：

1. 问题、对象/证券、研究与价格截点、版本、用途和产出方式。
2. 商业质量、边际经营、现金/融资、证券经济性分别给出判断。
3. 行业背景、竞争与关键业务驱动，解释指标为什么重要。
4. 核验实际、可比季度/累计、调整和现金勾稽；重要数值可下钻原文与算式。
5. 经营/事件→盈利→现金→资本→估值的传导，列明时滞与抵消。
6. 已知价格条件、情景及不支持的估值用途，不混入默认目标价。
7. 最强反方、联合压力、先坏在哪里、资金/履约约束。
8. 缺口、可信度理由、下一验证及触发重审条件。
9. 相对旧版改变了什么、哪些判断保持、变更原因和未解决分歧。
10. 来源位置、公式/假设、方法版本、利益关系与引用限制。

保存报告不等于批准评级；动态报告的较新市场背景也不意味着旧模型已自动重算。专题报告按冻结截点发布，后续新增版本，不静默覆盖原稿。

## 8. 结论、可信度和研究动作

| 输出 | 合法表达 | 必要前提 |
| --- | --- | --- |
| 经营方向 | 正向、负向、混合、无明显影响、无法判断 | 明确对象/期间和比较基准 |
| 因果解释 | 支持程度、反方、适用/失效条件 | 不用数据相关性直接宣布原因 |
| 证券经济性 | 已验证的价格条件或仍缺哪些估值输入 | 完整度单独审议；不以经营增长替代现价吸引力 |
| 事实与机制信心 | 高/中/低或不足，并说明来源/可比/独立性 | 不从大模型自评或引用数量机械换算 |
| 概率预测 | 事件、期限、结算与校准状态 | 未校准不显示已验证概率或成功率 |
| 下一动作 | 阅读、补证、重算、复核、等待或退出 | 当前不自动变成买卖、仓位或执行指令 |

资料缺失的门槛作用于相应层：缺现价不妨碍业务研究，缺税基不妨碍每单位税基压力演算，但会限制总利润判断。不能将所有未知合成一个无法解释的质量分。

## 9. 事件提醒、宏观与高危风险

每个提醒回答：发生/公开/生效时间、证据与确认状态、受影响对象、净暴露、量价成本/现金/融资通道、重要性理由、当前假设是否变化、下一行动和复核窗口。数据源失败另作健康提示，不能表示没有风险。

重大融资到期/契约、实际停产/停电、安全事故、关键限制/税制变化优先核查；一般价格波动先查因；小修订、转载和已解释消息去重留日志。提醒阈值需说明来自政策/合同、历史分布、公司指引或研究假设，未经校准不得称精准预警。

联合压力覆盖需求/净价、客户回款、供应商融资、CapEx、债务、币种与估值的相互作用。历史案例用来识别脆弱机制，分清当时和事后可知；不能保证提前预测黑天鹅，也不能给未经证据支持的尾部概率。

当前提醒以工作台和人工复核为主。定时运行、手机/邮件推送及对外消息渠道为后续方案，需先确认运行方式、预算、频率和噪声标准；未启动任何默认持续监控。

## 10. Agent与人工职责

拟定职责包括研究规划、来源检索、候选提取、会计/计算核查、行业/经营机制、反方与报告更新。每个角色均应有任务、证据范围、输入/输出、工具权限、失败/升级、费用和审计记录。

当前网站实现的是职责合同、规则和人工研究操作；专题曾使用同一AI体系分工研究，不是已上线的自主团队或独立机构审查。未来自动化按阶段推进：先候选与线索，再有证据的解释建议，再冻结输入的计算，最后由有资格的审议决定结论用途。外部来源文字不能成为角色系统指令；AI不得自行核验自己的候选或解除缺口门槛。

## 11. 关键使用旅程与异常

| 旅程 | 正常路径 | 必须可见的异常/结果 |
| --- | --- | --- |
| 首次研究一家汽车公司 | 选行业→问题→披露/字段→量价成本与现金→反方→条件稿 | 缺车型净价和海外暴露时保留补证，不能套同行参数称完整预测 |
| 财报后复核 | 定位新披露→比较可比实际→检查旧依赖→解释/补证→新稿 | 未读材料不进实际，旧稿仍在，失败/分歧不消失 |
| 宏观利率波动 | 核序列→看融资/折现暴露→判断合同及期限→条件测算 | 不直接给所有成长股相同目标价变化 |
| 双设备保存 | 读云版本→编辑→提交→确认成功 | 旧版本冲突拒绝覆盖，可导出未保存数据；网络未确认不显示保存成功 |
| 来源宕机或修订 | 保留旧观察、记录新尝试→提示健康/版本→复核 | 不以零补缺、重置旧观察日或悄悄回退旧年模型 |
| 阅读专题 | 第三层入口→固定截点全文→来源/算式/下一验证 | 不误认为今日自动更新或已形成投资建议 |

## 12. 验收标准与评价

产品验收分六层，单独公布：可访问/软件控制、原文与时点、财务算术、经营机制与预测、独立反方充分性、前瞻/决策效果。

| 条件 | 通过证据 | 不足时的处理 |
| --- | --- | --- |
| 三层均可独立阅读且左栏适配 | 实际页面、窄屏与路径检查 | 不能由桌面截图声称手机通过 |
| 关键结论可追来源/输入 | 相关原文/字段/定位及计算快照 | 不仅核URL存在或文件哈希 |
| 错期间、错定义、未来和冲突被阻止 | 先写的反例与原文基准 | 保留失败与缺口，拒绝静默回退 |
| 反方能修改判断 | 同类强反证审议、实际改判与保留理由 | 字数、角色数和赞成票不算充分性 |
| 新证据影响适用模型或用途 | 定义暴露/时滞的反例，同值重取不误报 | 缺机制则只提示复核，不伪装自动盈利更新 |
| 保存/版本/恢复可靠 | 多设备冲突、失败、恢复及原件检查 | 保存未确认冻结继续操作；旧稿不可覆盖 |
| 投资有效性可评价 | 预注册未见样本/前瞻、基准及到期结果 | 当前未通过；不把工程结果升级为投资能力 |

拟跟踪的质量指标：严重事实/口径错误、关键遗漏、无依据断言、正确保留未知、对结论有用的补证、真正改判、提醒噪声、用户核查成本、来源时效和保存失败。目标值在有实际基线后制定，不编造用户节约时间或收益改善。

## 13. 开发顺序与阶段条件

P0先深化研究内核：BYD量价/资金、CATL现金、CMB信用/资本，再完善微软/Costco/腾讯专门驱动；每条驱动先用原文和独立计算定基准、写反例，才能影响预测。P1补主数据/价格/FX/资本桥、公告覆盖、正常化和比较预期。P2改善可靠运行、知识与报告依赖，验证真实手机和恢复；按稳定性再扩大覆盖。P3在授权和预算明确后接独立模型/专家、持续任务和前瞻结算。

这不是承诺排期。按错误后果、可区分证据与用户价值排序；功能完成需要逐项验收，六家公司和专题是开发案例，不是未见测试集。
