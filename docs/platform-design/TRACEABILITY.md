## 3. 文档/实现状态的冲突处理

旧文件描述的是其日期的范围与建议；本目录整合到0.6及专题状态。发现冲突时按用户最新明确要求→实际源码/数据→对应日期验收→设计建议定位差异，不用文档语气替代证据。例：数据库实际为SQLite；站点已私有发布；原文按需获取；通用情景仍是示例；40个行情观察不等于40套盈利预测。

新增功能应将需求条目链接到F合同和实际证据；暂未实现的领域对象/API保持规划。本文不将原来AC-01～26改成已通过，追加AC只描述检查条件，结果由运行与审议记录给出。

## 4. 方案更新检查清单

1. 这个变更改善哪个判断，对应用户明确要求还是设计建议？
2. PRD输入/输出、失败、用途和验收是否改变？
3. 技术源路径、实际表/接口、时间/数字/依赖/权限是否改变？
4. 原始资料与假设是否可区分，旧稿/错误是否保留？
5. F合同、质量门、人工审议和实际能力状态是否各自更新？
6. 仅Git文档同步，还是涉及网站源码发布或用户数据迁移？三个动作是否分别验证？
