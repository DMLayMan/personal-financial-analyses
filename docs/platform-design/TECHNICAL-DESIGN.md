# Personal Financial Analyses 技术设计

文档版本1.0｜整理日期2026-10-27｜应用基线0.6｜对应[PRD](PRD.md)。以下区分当前源码事实、领域合同和后续设计，不把数据库建议写成实际迁移。

## 1. 技术目标与决定

同一套研究规则连接证据、财务算术、假设、反方、结论和版本；每个重要输出可追到输入。先保持单人研究可运行、可恢复和可审议，再扩展自动化与覆盖。研究逻辑以Python模块为主，财务数值使用Decimal，不能为托管方便另造结果不同的JS估值内核。

| 决定 | 当前方案与原因 | 演进条件 |
| --- | --- | --- |
| 应用结构 | 模块化单体与有界任务；便于单人追踪事务和研究依赖 | 真实并发/任务规模、常驻需求和运维能力证明需要拆分 |
| 本地存储 | SQLite/WAL，JSON业务记录、追加审计与jobs | 多用户隔离、检索和长任务需要时再评估服务端关系库 |
| 数字合同 | 原始金额/比率用十进制字符串进入Decimal，展示时舍入 | 新模型须逐项定义单位/精度/税/股数与独立验算 |
| 本地UI | 原生HTML/CSS/JS，Python loopback HTTP | 组件复杂度实际需要时再决定前端重构 |
| 私有云 | Vinext/Worker JS宿主、浏览器Pyodide、D1版本指针与R2不可变内容 | 共享、常驻计算或浏览器容量不足时须另做架构与权限验收 |
| AI | 当前无外部模型自动研究服务；规则/人工流程不冒称自主Agent | 授权、预算、输出合同、证据相关性/反方基准具备后逐项接入 |
| 远端源码 | GitHub私有主仓库；Sites另有发布源码与构建版本 | 推送GitHub不等于发布站点；发布代码不覆盖用户数据 |

早期[方案基线](../solution-design.md)建议过PostgreSQL，但实际本地采用SQLite，理由保存在[ADR0001](../decisions/0001-local-runtime.md)。PostgreSQL、向量数据库、独立队列和原生App均未成为当前默认实现。

## 2. 运行拓扑

### 2.1 本地

浏览器 → `pfa.server`（默认127.0.0.1:8765）→ `Platform/Research` → 来源/知识/市场/报告模块 → Decimal模型和SQLite/本地原件。

`pfa.service`管理后台进程、实例归属、启动/停止/重启、日志和doctor，避免启动会话结束后地址失效。后台任务按队列执行原件、市场和信息获取；有任务队列不代表已启用定时监控。模型或知识目录改变后重启加载运行摘要，旧结论按依赖提示重审。

### 2.2 本人私有云

1. Sites本人登录边界保护站点和数据。Vinext服务端返回工作台壳、固定依赖及源代码包。
2. 页面启动Web Worker，加载固定Pyodide、Python标准库及必要包，把纯Python模块、知识和本地只读文档写入浏览器文件系统。
3. 浏览器从同源云接口获取当前研究数据库与原件；逐文件核摘要，SQLite在Worker内执行，UI不承担金融计算。
4. `BrowserBridge`提供与本地一致的研究资源合同；外部网络通过受限同源来源代理，Python仅消费本轮取得的响应。
5. 本地研究修改成功后生成一致性数据库快照，先上传不可变原件和数据库，再用D1前序版本比较并交换提交新指针。
6. 关闭页面后不继续研究或取数。云端保存可跨设备读取，但没有常驻Python服务器、自主AI或连续监控。

人工专题HTML作为静态出版物单独交付，不需要先启动完整浏览器Python与证据包。动态公司报告由当前研究台账组合；二者共用方法纪律，但生成方式、信息截点和更新链不同。

### 2.3 架构边界

私有云当前工作区固定为`owner-private`，不是生产多租户模型。普通研究云接口还检查经过上游提供的登录标识；`/cloud/admin/*`服务导入路径依赖同一owner-private边界。扩大受众前必须重新设计每个工作区、对象授权及导入接口，不能只将站点设为公开。

## 4. 存储：实际实现与领域模型

### 4.1 当前SQLite表

| 表 | 主要字段 | 实际职责 |
| --- | --- | --- |
| `records` | id、kind、issuer、payload、created_at | 类型化JSON业务记录，按kind/issuer索引；不是每类对象一个专表 |
| `audit` | sequence、issuer、action、payload、created_at | 单调序列与操作轨迹，支持修订和报告一致性 |
| `meta` | key、value | 应用元信息 |
| `jobs` | id、issuer、payload、status、attempts、error及时间 | 持久任务和失败/重试；不等于定时调度系统 |

`Store.tx()`使用WAL、busy timeout和`BEGIN IMMEDIATE`，成功提交、异常回滚。JSON中金额保留十进制字符串，模型通过Decimal解析；数据库不依赖SQLite浮点来证明财务精确。业务修订通过新记录/审计追加表达，任务状态等运行元数据可更新。当前没有每个对象的数据库行级多租户授权。

### 4.2 领域合同

下列是分析领域的逻辑合同，并非宣布所有字段已有独立数据表或完整CRUD：

| 对象 | 至少应保留 | 当前覆盖与扩展 |
| --- | --- | --- |
| Issuer/Security | 发行人、证券、市场/柜台、币种、股本、有效期/公司行动 | 六公司配置及专题人工数据存在；完整历史证券主数据待建设 |
| Source/DocumentVersion | 来源类型、实体、公开/取得时间、原件/摘要、版本/位置、能力状态 | 文件/元数据/定位部分已实现；逐字段/持续授权覆盖未完整 |
| Fact/DerivedFact | 原始/标准值、单位/币种/范围/会计口径/期间、分类、原文及计算输入 | 候选/核验、冲突/可比及选定算术有控制；语义充分性需审议 |
| Claim/Hypothesis/EvidenceLink | 判断、竞争解释、方向/相关性、上游与反证 | 研究台账/报告部分支持，不能用引用存在替代相关性 |
| Gap/FollowUp | 限制层、缺口类型、翻转条件、区分证据、状态和停止理由 | 待审补证与未知保留；自动语义裁定未实现 |
| Event/MarketObservation | 发生/公开/生效、对象、序列定义、前值/修订、暴露/时滞 | 选定元数据和人工事件，尚无自动宏观归因改模型 |
| ModelVersion/Run | 公式/参数版本、冻结输入、分类、单位、精度、结果与用途 | 通用示例和局部历史桥；行业全套预测待逐项补齐 |
| Review/Conclusion/ReportVersion | 主判断、强反方、裁定、用途、依赖、旧版与变化理由 | 草案/版本与失效控制已实现一部分；独立审议未验证 |
| Forecast/Settlement | 事件、首次登记、期限、概率、结算源、结果与排除理由 | 长期设计，不能称已建可校准前瞻系统 |

未来迁移专门关系表时须保留旧ID、来源/版本、审计序列和计算结果，先隔离回放对比，再迁移；不能为改进成绩删除旧失败。

## 5. 时间、数值和证据合同

### 5.1 时间

至少区分经济期间、事件发生、首次公开、系统取得和政策/合同生效。价格另保留当地交易日/时段、市场和复权口径。新文件公开不证明文件中的旧事实已经更新。源码当前部分门槛使用日期粒度，并不具备全市场分钟级point-in-time事件库。

当前历史实际筛选要求`period_end ≤ published_at ≤ 审查日`，并检查单位、币种、范围、口径和可比期间。存储时间戳采用UTC；产品显示需保留原市场与用户Asia/Shanghai时区。完整交易/披露日历、修订历史和假设时点回放仍需扩展，不能把当前版本的Yahoo历史日线称真正历史可知快照。

### 5.2 数值与分类

原始数值不先舍入；保存单位/缩放和币种，进入计算再标准化。累计转单季、TTM、同比、证券换算必须保留公式、输入和定义；负/零基数保留绝对变化，百分比不适用时明确说明。

当前历史候选分类白名单为`fact_source_reported`、`fact_provider_standardized`、`derived_calculation`；其他如`issuer_management_claim`、`management_adjusted`、`analyst_adjusted`、`estimate_consensus`、`scenario_assumption`等单独表达。分类允许进入候选筛选不等于原文语义核验已经完成，派生值仍需追全部输入。

利润/税/股本、现金/短债证券/权益证券、债务流动/非流动、预付款/承诺/已付、现值/未折现要分别定义。不能把税前投资收益直接减税后净利，不能季度乘四冒充TTM，不能在总现金CapEx后重复扣同一研发现金，不能把RPO/ARR/融资承诺当已实现营业收入或收款。

### 5.3 依赖与失效

运行内核摘要冻结在进程启动时，包括指定核心Python模块和`knowledge/*.json`。全部源码是否与质量门运行一致由更广的`source_manifest`检查；这两种摘要不能互相替代。原件哈希证明字节一致，不证明字段、机制或预测正确。

报告依赖包括公司证据/模型/结论、采用方法、市场观察、事件/未读提交、行业手册及运行内核。比较市场经济观察而非仅取得时间；同值重取不产生虚假经济变化。输入/政策改变时旧稿提示复核；保存本身不应使报告自动失效。当前所有依赖影响仍有开发边界，不承诺任意外部变化均被自动识别。

## 6. 资料与研究数据流

### 6.1 获取到核验

1. 按研究问题确定字段与主/备来源；先区分不存在、未取得、已有未提取和口径待核。
2. 显式入队；公司原件、`_market`、`_information`使用不同消费空间，避免相互误处理。
3. 核HTTPS、域名/路径、身份与受限重定向，保存原始响应、取得时间、摘要、失败和修订。
4. 解析元数据/候选字段与页码、单位、期间、范围；网页脚本壳/空值/超限不能称读取正文成功。
5. 人工核验并提出冲突；关键基线冲突暂停相应模型，不静默降级旧年。
6. 确定性派生、方法/报告依赖和重审提示；管理层说法/标题不因抓取成功而进入已报实际。

任务结束只表示本轮操作结束；不自动关闭未知、批准反方或生成投资意见。公开来源当次成功不提供长期SLA。

### 6.2 更新到报告

读取审计游标和当前输入→构造可比观察→连接机制/现金风险→带入行业/方法/市场→检查用途门槛→复查游标→返回草案。保存时验证预期修订/依赖，拒绝用过期页面覆盖新输入；保存追加报告快照与理由，旧版仍可读取。

当前市场变化只构成背景/待审事件；缺公司净暴露、合同、时滞及预测桥时，不能自动修改盈利参数。真正行业预测更新需另定义驱动合同和反例，例如同销量、不同净价/成本应导致不同利润及资金需求。

### 6.3 人工专题出版

`research/2026-10-25/`保存选定字段、来源登记、假设、交叉审查、价格参考、确定性诊断和HTML。原始下载保留在忽略的`data/`。`knowledge/research-publications.json`列固定日期、标题、路径、路由和SHA；本地只按目录白名单读取，拒绝越界/篡改。托管构建核对相同摘要并复制静态正文。

本轮两篇专题是人工研究和确定性排版，不是在线自动Agent任务。后续研究更新应新增带日期/版本的产物并说明改判，不让重新运行抓价脚本静默改变已经发布的研究截点。生产静态服务可能把`.html`规范化为无扩展名并附加边缘检测脚本；验收作者正文与边缘追加应分别记录。

## 7. 现有接口与通信合同

### 7.1 本地/浏览器研究资源

| 接口族 | 当前用途 | 修改控制 |
| --- | --- | --- |
| GET `/api/healthz`、`/api/bootstrap` | 运行状态、实例/内核及启动数据 | 本地Host范围；云端桥返回浏览器运行状态 |
| GET `/api/platform`、`/api/industries`、`/api/library/{id}` | 方法、行业、功能与白名单只读文档 | 不允许任意文件路径 |
| GET `/api/markets`、`/api/information` | 观察、来源尝试、公告元数据 | 与财务核验状态分开 |
| POST `/api/markets/refresh`、`/api/information/refresh` | 显式按需入队 | 本地令牌/同源；云端适配后保存 |
| GET `/api/companies/{issuer}`、POST `/api/companies/{issuer}/{action}` | 原文、事实、核验、模型、反方与结论命令 | 发行人、命令合同与预期修订；错误不静默成功 |
| GET `/api/documents/{id}`、`/api/export/{issuer}` | 受限原文定位与结构化导出 | 记录类型/路径检查，非任意磁盘读取 |
| GET `/api/knowledge`、POST同路径 | 知识版本 | 草案/采用/停用及预期修订 |
| GET `/api/reports/{issuer}`、POST `/api/reports/{issuer}/snapshot` | 草案和追加快照 | 依赖/审计游标及变更理由 |
| GET `/api/reports/{issuer}/document`、`/api/report-versions/{id}` | 独立HTML/历史稿 | 保留旧版，不因导出解除评级限制 |
| GET `/reports/{issuer}`、目录中的`/research/*.html` | 人类可读报告 | 本地动态报告与静态专题分开；托管端路由适配见源码 |

浏览器研究API由桥适配，不是云端Python HTTP服务器。具体错误和字段以`server.py`、`cloud_bridge.py`及回归为准，文档不另造第二套响应结构。

### 7.2 云持久化接口

GET `/cloud/state`、`/cloud/revisions`读取当前指针/版本；GET/PUT `/cloud/blobs/{sha256}`读取或幂等上传不可变内容；POST `/cloud/commit`提交数据库SHA、原件清单和`expectedVersion`；POST `/cloud/retrieve`走受限公开来源代理。只有服务导入工具使用对应`/cloud/admin/*`路径，不能作为公开应用接口暴露。

写请求检查`X-PFA-Request: 1`、Origin和跨站标识；客户端不能自造可信身份绕过Sites登录。普通来源代理核每跳域名/路径，超限/空响应/非成功状态失败，不提供任意URL代理。当前来源白名单限选定公司/监管站点及Yahoo/FRED/Fed路径，工具能访问某服务不代表站点已部署同一连接。

## 8. 云端保存、并发与恢复

### 8.1 保存事务

页面在内存SQLite完成一次研究操作→生成一致性快照→上传尚未存在的原件/数据库SHA对象→验证对象尺寸/摘要和SQLite签名→以当前`expectedVersion`提交→D1 CAS更新工作区头并追加修订。

相同前序版本两个客户端只能有一个更新成功，另一方返回409；冲突客户端导出未保存记录后重新读取，不能盲目重试覆盖。上传成功但尚未提交指针的对象不代表研究已保存，旧头继续有效。网络未确认/保存失败后，前端暂停继续修改，明确未保存状态。

### 8.2 当前约束

数据库快照上限16MiB；单对象上限25MiB；原件目录最多500项。超限拒绝提交，不截断或丢记录。全部状态首次导入曾约59MB，另有Python运行时；这是历史实际，不是每设备当前加载大小/延迟保证。流式增量、离线编辑和无提示自动合并没有实现。

### 8.3 恢复

本地按运行手册备份SQLite一致性快照及原件索引/文件，隔离目录恢复并做数据库和摘要检查。云端从旧不可变快照恢复到隔离环境核查，再以当前版本显式提交新修复版本；不覆盖旧修订。代码回滚使用对应Sites保存版本，数据回滚不能由代码发布自动推定完成。

首次迁移器只接受云端v0；已有云数据不得重播初始化包覆盖。本地与云端首导后各自版本化，当前无自动双向同步，也不因推送GitHub更新研究数据库。

## 9. 安全、权限与外部内容

本地默认loopback，核Host、修改令牌及Origin；只读文档、原件和专题按目录/类型/摘要约束。报表外部文字需要转义，不应形成任意脚本；专题允许的固定样式/脚本在本地以摘要约束。

凭据、持仓、数据库、下载原件和缓存不进Git；私有仓库不替代忽略规则。源访问凭据只在会话/标准输入使用，不写命令行、代码、报告或构建包。HTML/PDF/公告内容一律是数据，不是执行指令；未来模型服务必须延续同一信任边界。

当前对第三方全文的读取、保存、再展示能力应按来源分别核实；公开可读不等于自动拥有再分发许可。新增付费源或共享用户前，需要确认合同和最小权限；本方案不虚构已完成法律审查。

## 10. 验证、可观察性与发布

每项功能先写F合同与失败方式。涉及金融计算先确定原文答案/独立基准，缺陷先复现，才能修改实现；不写只镜像代码的测试证明有效。

| 验证面 | 当前证据/需要的记录 |
| --- | --- |
| 工程与控制 | `tests/`、Node云策略、质量门逐项结果和当前源码摘要 |
| 财务与时点 | 原文定位、同口径输入、Decimal独立算术、未来/冲突反例 |
| 页面和访问 | 真实本地/托管页面、失败与设备范围，不以本地CPython代替浏览器Python |
| 保存/恢复 | 双写冲突、网络失败、旧快照/原件、重载与迁移边界 |
| 研究效果 | 语义相关性、行业归因、独立反方、未见样本/前瞻，单独记录未验证 |

`scripts/quality_gate.py`生成运行命令、Git基线、工作区状态、源码清单、测试和来源/服务记录。`--verify-only`比较既有结果与当前代码。只读文档调整不等于重新验证投资方法；未运行的浏览器/金融/专家项目必须明示。

源码修改后本地回归与服务检查→同步纯源码到站点kernel并校验清单→构建固定依赖/专题→推送Sites源版本并私有发布→核原生发布状态、作者正文/源码与数据保留。GitHub是完整项目与文档远端，Sites是部署源码与产物远端；两者提交号不同是正常现象，验收中分别记录，不冒称GitHub push自动发布。

运行记录至少覆盖任务状态/失败、来源观察/取得/修订、未读披露、输入冲突、报告失效、云版本冲突、保存/恢复和内核摘要。尚无已验收的全天SLA、外部告警服务或自动容量扩展承诺。

## 11. 扩展设计与迁移次序

### 11.1 行业驱动与定价优先

先建立逐行业字段/公式/现金/融资合同，并把最新实际滚动到未来假设；再补历史证券身份、完全稀释股本、FX和完整资本索偿。未知不得用通用增长或PE替代。每个驱动都需要独立敏感性与资金压力反例，才能接到结论更新。

### 11.2 自动研究编排（规划）

以ResearchCase为根，任务引用冻结资料与方法版本。模型网关负责供应商/模型/提示版本、结构化输出、费用、超时与工具权限；角色输出候选/解释/补证建议，核验和结论用途分别审议。任务须有幂等键、重试边界、审计和人工接管。先证明候选相关性/引用支持/反方能改判，再考虑自动推进，不用Agent数量衡量质量。

### 11.3 持续监控（规划）

需要页面外可信的调度/计算宿主，而非仅靠浏览器定时器。每源保存日历、修订、限额、健康和最后成功；事件幂等/去重，提醒按规则版本与研究依赖生成。渠道、运行时段、预算和噪声目标先确认。关闭页面后运行、秘密后台监控及邮件发送均不属于当前部署。

### 11.4 多用户与更大数据量（规划）

先做身份/工作区/对象授权和服务导入隔离，再评估服务端数据库与对象存储、任务宿主及检索索引；迁移保留版本、原件引用和Decimal一致性。向量检索只定位资料，不能替代时点过滤或判定引用支持。共享和公开发布另行确认，不沿用owner-private安全假设。

### 11.5 可验收的下一步

顺序为：公司经营/资金驱动→来源/主数据与价格条件→模型/报告的实质更新→语义审议基准→独立与前瞻评价→有预算和宿主的持续运行。是否换栈由已测瓶颈决定，不因方案写得完整就启动未经授权的付费服务或远程迁移。
